# Infrastructure (AWS)

Codename **project-sable**: infrastructure, buckets, images and the repository use the codename, not the product name.

## Shape

One EC2 instance (`t3a.medium`, Amazon Linux 2023, Singapore `ap-southeast-1`) runs the application containers with Docker Compose; the database is a separate managed **Amazon RDS PostgreSQL** instance in private subnets. Background analysis runs in-process in the web container, so no queue service is needed.

```
Internet ──443──▶ Caddy (automatic HTTPS) ──▶ web (SvelteKit Node server)
                                                 │  ├─▶ RDS PostgreSQL 17 + pgvector (private subnets, TLS)
                                                 │  ├─▶ voice (FastAPI + pyannote, CPU)
                                                 │  ├─▶ S3 (case originals, private, TLS-only)
                                                 │  └─▶ Bedrock (Nova 2 Lite screen, Claude Sonnet 4.6 review)
GitHub Actions ──OIDC──▶ ECR push ──▶ SSM RunCommand ──▶ /opt/<project>/deploy.sh
```

| Piece | Choice | Why |
|---|---|---|
| Compute | 1 EC2, Docker Compose, Elastic IP | Simple, cheap, no cold starts for pyannote |
| Access | SSM Session Manager | No SSH key, no port 22 |
| Database | Amazon RDS PostgreSQL 17 (`db.t4g.micro`, gp3, encrypted, 7-day backups with point-in-time restore, deletion protection, `rds.force_ssl`) | Relational case data, transactions, full-text search and pgvector in one engine; managed and independent of the app server |
| Files | S3, private, SSE, TLS-only policy | Replaces Supabase Storage |
| AI | Bedrock through the instance role: `global.amazon.nova-2-lite-v1:0` (screening, assistant, practice) and `global.anthropic.claude-sonnet-4-6` (independent review) | No API keys. Both are global cross-Region profiles (the only profiles these models have in ap-southeast-1), so inference may run outside Asia Pacific. Choice and benchmark: [`docs/phases/2026-11-02-model-choice.md`](../docs/phases/2026-11-02-model-choice.md) |
| Images | ECR (last 5 kept, scan on push) | Built by GitHub Actions on x86 runners |
| Secrets | SSM Parameter Store SecureString (DB password, voice token) | Generated by Terraform |
| HTTPS | Caddy + Let's Encrypt on `<elastic-ip>.sslip.io` unless `domain` is set | The browser microphone requires HTTPS |
| Budget | Account-wide AWS Budget measured **before credits**: emails at $10 and $30 actual spend and at $80 forecast (`budget_*` variables, email in the gitignored `terraform.tfvars`) | With credits applied the net bill is $0, so a default budget would never alert |

Rough monthly cost at low use: instance ~$27, RDS db.t4g.micro + 20 GB ~$15, 40 GB gp3 ~$4, Elastic IP ~$4, snapshots/S3/ECR ~$1–2, Bedrock about $1.60 per two-hour hearing (about 360 witness turns screened by Nova 2 Lite at about $0.0044 each, plus a few Sonnet 4.6 reviews at about $0.04 each). Prices change; check the AWS console.

## Database and retrieval decisions

- **PostgreSQL** fits the data: cases, documents, chunks, hearings, statements, findings and links are relational, and findings must stay consistent with the quotes they cite. Full-text search and optional pgvector live in the same transactional engine.
- **Not DynamoDB**: no full-text or vector search (another service would be required) and a full data-layer rewrite. **Not DocumentDB**: ~$60+/month minimum, Mongo rewrite, weak Indonesian text search.
- **Retrieval (RAG)**: per-case PostgreSQL search sends the top 8 passages for each statement; Bedrock screens with Nova 2 Lite and only potential inconsistencies go to Claude Sonnet 4.6 for independent review. Bedrock Titan embeddings with pgvector can be added without new services. **S3 Vectors** is reserved for a future large corpus (for example tens of thousands of Supreme Court decisions), not case-sized document sets.

## First setup

```bash
cd infra/terraform
terraform init
terraform apply                     # ~5 minutes; prints url, instance_id, buckets, role ARN

# GitHub repository settings (the workflow reads these)
gh secret set AWS_DEPLOY_ROLE_ARN --body "$(terraform output -raw github_deploy_role_arn)"
gh variable set AWS_REGION --body ap-southeast-1
gh variable set PROJECT_NAME --body project-sable
gh variable set DEPLOY_INSTANCE_ID --body "$(terraform output -raw instance_id)"
gh variable set DEPLOY_OPS_BUCKET --body "$(terraform output -raw ops_bucket)"
gh variable set APP_URL --body "$(terraform output -raw url)"
```

Then push to `main`: `.github/workflows/deploy.yml` runs web and voice checks, builds both images, pushes them to ECR, uploads `infra/docker/` to the ops bucket and runs `deploy.sh` on the instance through SSM, then smoke-tests `/api/v1/health`.

The GitHub deploy role trusts only the `main` branch of `github_repository` through OIDC, accepting both the classic `repo:owner/name` subject and GitHub's immutable `repo:owner@id/name@id` subject (`github_immutable_subject`, from `gh api repos/<owner>/<repo>/actions/oidc/customization/sub`); no AWS keys are stored in GitHub. The account already has the GitHub OIDC provider, so `create_github_oidc_provider` defaults to `false`.

## Changing the Bedrock models

The instance role may invoke any foundation model and inference profile (`bedrock:*::foundation-model/*` also matches the Region-less model ARNs of global profiles), so a model change needs no IAM change. The model IDs reach the web container through `/opt/<project>/instance.env`, which user data writes only on first boot: a new `bedrock_model` default in Terraform affects new instances only, and applying it to the running instance stops and starts it to rewrite user data. On the running instance, edit the file and redeploy instead:

```bash
aws ssm start-session --target <instance_id>
sudo sed -i 's|^BEDROCK_MODEL=.*|BEDROCK_MODEL=global.amazon.nova-2-lite-v1:0|; s|^BEDROCK_REVIEW_MODEL=.*|BEDROCK_REVIEW_MODEL=global.anthropic.claude-sonnet-4-6|' /opt/<project>/instance.env
sudo /opt/<project>/deploy.sh <current-git-sha>
```

Third-party models (Anthropic, Moonshot, OpenAI) are Marketplace products that subscribe on first invocation. The instance role has no `aws-marketplace:*` permission, so invoke a new third-party model once from an administrator (for example `pnpm tsx scripts/benchmark-chat.ts --models <id>` in `apps/web`) before switching production to it. Default quotas in this account: 20 requests/minute for Nova 2 Lite and 10 for Claude Sonnet 4.6. Analysis runs three statements at a time with adaptive SDK retries.

## Operations

- Shell: `aws ssm start-session --target <instance_id>` then `cd /opt/<project> && sudo docker compose ps`.
- Logs: `sudo docker compose logs -f web`.
- Manual deploy of a tag: `sudo /opt/<project>/deploy.sh <git-sha>`.
- Database restore: RDS point-in-time restore (console or `aws rds restore-db-instance-to-point-in-time`), then point `DB_HOST` at the new endpoint.
- Instance volume restore (model cache, Caddy certificates): the latest `Backup=<project>-daily` snapshot.

## State

Terraform state is local (`infra/terraform/terraform.tfstate`, gitignored) and contains the generated secrets. Keep it private, or move it to an S3 backend with `terraform init -migrate-state` before sharing the project.
