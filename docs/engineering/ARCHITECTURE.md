# Architecture

Svelte 5 and SvelteKit 3 serve the landing page, workspace, and TypeScript `/api/v1` API from one Node 24 server built with `@sveltejs/adapter-node`. Production runs that server in Docker on one EC2 instance next to PostgreSQL, with originals in S3 and AI through Amazon Bedrock (see [`infra/README.md`](../../infra/README.md)). Server modules are under `apps/web/src/lib/server`; the catch-all endpoint delegates to `api.ts`. Zod validates requests, portable records and model output. Private environment variables are declared explicitly in `apps/web/src/env.ts`. No frontend proxy or app-hosted WebSocket is required; the Python voice service in `apps/voice` is optional.

Opaque account cookies are HttpOnly and SameSite Strict, with Secure in production. Scrypt hashes and hashed 12-hour session tokens retain compatibility with the previous implementation. Every case route, notification stream, file download and conversation verifies ownership. API mutations reject foreign origins. Browser database roles have no table access.

The typed SQL layer uses `node:sqlite` locally and `pg` for PostgreSQL. Existing table names, JSON data, IDs, account hashes and migrations 001–005 are preserved. Migration 006 adds audio session state and 007 adds voiceprints. Migrations live in `db/migrations`; `db/migrate.mjs` (its own image) applies them to PostgreSQL (Amazon RDS in production) before the server starts (it first creates the few Supabase-era objects the older migrations reference), so the server never creates schemas at startup. A local SQLite process creates/additively upgrades its schema and marks abandoned local work interrupted. Original files remain separate from extracted chunks: in a private S3 bucket when `S3_BUCKET` is set, otherwise in the local data directory. Documents record their storage (`s3` or `local`) so either kind stays readable.

## Evidence and analysis

Document ingestion preserves page boundaries and originals, limits files/text/pages, serializes duplicate/quota checks through commit, and removes uncommitted originals after database failure. PDF.js handles text PDFs; `fflate` and a bounded XML parser handle DOCX. Scans require prior OCR. Embedding failure retains labeled keyword search. Retrieval filters case and embedding model, combines term overlap and cosine scores, and supports the existing pgvector schema/index.

Each analysis extracts a checkable claim, retrieves evidence, asks an analyst, asks an independent reviewer without the analyst's answer, then synthesizes a qualified finding. Exact quotes and required citation relationships are checked before persistence. Imported hearing originals are excluded from their own analysis. Citation checks establish provenance, not semantic correctness or truth.

Analysis runs in the web process after testimony is saved: at most three statements analyze at once, at most 100 wait, and duplicate retries of one statement coalesce. PostgreSQL or SQLite leases prevent concurrent duplicate work on shared operations, and provider calls have deadlines. Failed or interrupted analysis is retried manually per statement. Expired audio sessions, socket tickets, rate buckets and leases are cleaned opportunistically when cases load. Case notifications use cookie-authenticated SSE with session revalidation and bounded stream duration; reconnect and periodic polling reload authoritative state.

## Audio and files

The server presigns an Amazon Transcribe streaming WebSocket URL (SigV4, valid five minutes to connect, `id-ID` or `en-US`, partial-result stabilization) after checking the user's recording authorization, hearing and active-session lease (`src/lib/server/transcribe.ts`, `audio.ts`). The browser connects directly to Transcribe and sends PCM from an AudioWorklet in AWS event-stream frames (`src/lib/aws-eventstream.ts`). The server's AWS credentials (the instance role in production) never reach the browser. The server API authenticates finalized transcript batches, validates and splits speaker turns, adds timeline offsets, and atomically saves ordered batches before queuing their analysis. Duplicate retries do not create repeated testimony. Speaker IDs are scoped to each connection and are never inferred courtroom identities.

A Transcribe stream can last four hours, so the browser rotates after 3 h 50 min: the worklet flushes the old connection, captures into a bounded reconnect buffer, then resumes transmission on a freshly presigned URL. Final stop waits for final transcription and HTTP persistence. Errors explicitly prompt users to inspect final saved words. Partials stay in the recording browser; saved turns notify other views. An open stream can continue after sign-out, but revoked sessions cannot save additional testimony. Browser-relayed output is not provider-attested evidence.

Alongside transcription, the browser records the same microphone stream with MediaRecorder (Opus at 32 kbps where supported) once the user confirms that the presiding judge allowed recording. The recording uploads when capture stops (`POST /cases/:id/recordings`, at most 64 MB) and transcription never waits for it. Recordings are stored privately (S3 under `S3_BUCKET` in production, the local data directory otherwise), listed per hearing, served with HTTP Range support for seeking (`src/lib/server/recordings.ts`) and deletable. They are removed with their case and are not part of `.jude` archives.

Uploads are single bounded multipart requests (25 MB for documents, 6 MB for hearings, the archive limit for `.jude` imports); the Docker image raises the adapter body limit to match. Originals and exports return their bytes directly with the stored Content-Type and an attachment Content-Disposition.

## Voice service

Amazon Transcribe speaker labels (`spk_0`, `spk_1`) last for one connection, so saved turns are keyed `<session>:<label>`. When `VOICE_API_URL` and `VOICE_API_TOKEN` are set, the recording browser keeps the last two minutes of captured PCM in memory. After a batch saves, it cuts each finalized turn of at least 3 s (capped at 25 s), resamples it to 16 kHz WAV and posts it to `/api/v1/cases/:id/transcripts/:segment/voice`. The server checks ownership and origin, then calls the Python service's `/v1/identify` with the case's voiceprints for the active model.

A match above the threshold updates that voiceprint's running mean; otherwise a new `voice-N` print is created. The first identification of a provider label claims all its turns and re-keys them to `voice:voice-N`; later saves of that label are keyed directly. Disagreements move only the statement that was heard. User labels attach to `voice:` keys, so one name survives new connections and hearings. Voiceprints live in `jude_voiceprints`, are excluded from `.jude` archives and can be deleted per case. The Python service is stateless and never stores audio. Clip upload failures are ignored because the transcript is already saved.

## Hearings, archives and conversations

Hearing import is preview/confirm with deterministic native parsers or explicitly requested AI formatting. Imported words must occur in the upload; conversion cannot decode scans or invent speaker identities/timestamps. The original is saved as a private case document. `.jude` version 1 remains a bounded ZIP manifest plus originals, with checksums, provenance and reference checks. Import creates new IDs and resets imported finding/link review state. Practice and assistant history have separate JSON exports.

The evidence graph uses up to 300 indexed passages, compares the first 120 cross-document passages for at most 12 suggestions, and verifies both quotes for AI relationships. Search covers case passages and expands through confirmed connections only. Similarity does not imply support or contradiction.

Case assistant context is bounded to selected document/testimony excerpts, inventory, recent findings and confirmed links. Conversations are owner-scoped and exchanges save atomically with idempotent request IDs. Practice freezes editable trial conditions at session creation and requires an AI provider (`src/lib/server/practice.ts`). AI speaks only other roles, cites case facts, adds an optional coaching note per turn and writes a cited debrief stored as one message per item. Sessions from the retired scripted drill stay readable but cannot continue. Practice never creates evidence, testimony or findings.

The product retains its existing visual identity and review workflow. Old-case responses cannot overwrite active-case state, and unsaved review-note drafts remain explicit. Tests cover local API behavior, PostgreSQL coordination, browser workflows, provider contracts, audio worklet flushing and direct-stream rotation. Amazon Transcribe streaming and Bedrock were verified in production on 2026-11-02. Pasal.id, S3 and the voice service still need an authorized live acceptance run.
